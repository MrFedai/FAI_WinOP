# FAI_WinOP

[![CI](https://github.com/MrFedai/FAI_WinOP/actions/workflows/ci.yml/badge.svg?branch=dev)](https://github.com/MrFedai/FAI_WinOP/actions/workflows/ci.yml)

A profile-driven, object-based optimizer for Windows 11. One command after a fresh install: the settings, apps and
desktop / taskbar layout in a profile are applied. A snapshot is taken before every change, and `-Undo` returns to the
previous state from it.

Open an **administrator** PowerShell and run one of these.

**Preview** — shows what would change; writes nothing:

```powershell
& ([scriptblock]::Create((irm https://github.com/MrFedai/FAI_WinOP/releases/latest/download/get.ps1))) -Profile fedai -DryRun
```

**Run** — applies the `fedai` profile:

```powershell
& ([scriptblock]::Create((irm https://github.com/MrFedai/FAI_WinOP/releases/latest/download/get.ps1))) -Profile fedai
```

## What the `fedai` profile does

When you run the profile, this is what happens, in this order:

1. **Elevation and user check.** The tool needs an administrator PowerShell (`-DryRun` too). If it was not started elevated, it asks for UAC and restarts itself. If the elevated account is not the owner of the desktop session, it stops (exit code 3) and names both accounts; `-AllowOtherUser` continues on purpose. If the session owner cannot be found, it warns and continues.
2. **Data folder and log.** The data folder under `%ProgramData%` is checked (only SYSTEM and Administrators may write); untrusted items are moved aside. A log file for the run is created and its path is printed.
3. **First steps** (before apps and the other tweaks):
   - System Restore point · `system.restore-point`
4. **Snapshots.** Before every change the current state is saved to a backup session; `-Undo` uses it. With `-DryRun` nothing is written, nothing is saved, and the planned changes are only listed.
5. **Apps** (12, from `apps/catalog.json`). Each is installed if missing; autostart entries and desktop shortcuts of the installers are removed and Start menu folders are flattened, except where the profile keeps autostart. Apps in the profile are protected from the bloat removal below.
   - Claude · winget · `claude`
   - Telegram Desktop · winget · `telegram` — autostart kept
   - WhatsApp · msstore · `whatsapp` — autostart kept
   - Discord · winget · `discord`
   - Steam · winget · `steam`
   - TradingView · winget · `tradingview`
   - Ollama · winget · `ollama`
   - Visual Studio Code · winget · `vscode`
   - Proton VPN · winget · `protonvpn`
   - Google Chrome · winget · `chrome`
   - Spotify · msstore · `spotify`
   - OBS Studio · winget · `obs`
6. **Tweaks** (27), in profile order, grouped by category. A tweak whose target state is already in place is skipped, and so is one whose condition does not match this machine. Caution tweaks ask for confirmation (`Y` / `N`); tweaks marked `Risk` ask you to type `YES`.
   - **setup**
     - Turn off background apps (except an exception list) · `setup.background-apps-off`
     - Microsoft Store: automatic updates, video and personalization off · `setup.store-optimize` — asks for confirmation
     - Default browser (via Settings) · `setup.default-browser` — asks for confirmation
   - **graphics**
     - NVIDIA: tray icon and legacy sharpening off · `graphics.nvidia-settings` — only if HasNvidia
     - AMD: simplified Adrenalin and low latency · `graphics.amd-settings` — only if HasAmdGpu
     - NVIDIA: stay in the P0 power state · `graphics.p0-state` — only if HasNvidia; asks every run, skipped with `-Unattended`
   - **ui**
     - Black theme (dark, transparency off, automatic accent, solid black wallpaper) · `ui.theme-black`
     - Lock and sign-in screen black · `ui.lockscreen-black`
     - Default account pictures black · `ui.account-pictures-black`
     - Taskbar: buttons off, tray in overflow, only File Explorer + Chrome · `ui.taskbar`
     - Turn off Widgets · `ui.widgets-off`
     - Turn off Copilot · `ui.copilot-off`
     - Notepad settings · `ui.notepad-settings`
     - File Explorer layout · `ui.explorer`
     - Reduce visual effects (font smoothing on) · `ui.visual-effects`
     - Turn off notifications (except an exception list) · `ui.notifications` — asks for confirmation
   - **bloat**
     - Remove unnecessary Store apps · `bloat.remove` — asks for confirmation
     - Keep removed apps from coming back · `bloat.persistence` — asks for confirmation
     - Remove Microsoft Edge (WebView2 stays) · `bloat.edge-remove` — asks for confirmation
   - **sound**
     - Turn off the startup sound · `sound.startup-sound-off`
     - Set the volume level (`level = 15`) · `sound.volume`
   - **privacy**
     - Minimize telemetry · `privacy.telemetry`
     - Turn off app permissions (camera and microphone stay on) · `privacy.app-permissions`
     - Turn off search and Start ads · `privacy.search-ads`
   - **power**
     - Power plan: high performance on AC, balanced on battery · `power.plan`
   - **system**
     - Timer resolution 0.5 ms · `system.timer-resolution`
   - **setup**
     - Windows Update: install pending first, then pause (`pauseDays = 365`) · `setup.updates-staged` — asks every run, skipped with `-Unattended`
7. **Taskbar, desktop and Start layout** (the profile's `layout` section):
   - Taskbar: alignment `center`, auto-hide on
   - Taskbar pins (2): `Microsoft.Windows.Explorer`, `Google Chrome`
   - Desktop icons shown: `recycleBin`, `thisPC`; hidden: `controlPanel`, `network`, `userFiles`
   - Desktop icon size: 48
   - Start menu layout: restored from the profile (`start2.bin`)
8. **Shell refresh.** Explorer, desktop and Start are refreshed once at the end, so the new look appears without signing out.
9. **Report and restart.** A summary lists every item as applied, up to date, skipped or failed (exit code 1 if anything failed). The tool does not restart Windows by itself. If a step needs a restart (for example Windows updates), the run stops there; after the restart the resume command continues the same session through `RunOnce`, or you run the same command again.

### Undo and what cannot be undone

`-Undo` reverts the last session in reverse order (`-Undo -DryRun` previews it; `-Undo -Session <id>` picks a session; `-SkipFailed` closes a session whose remaining entries cannot be reverted). Apps installed in that run are uninstalled; changed settings, services, tasks, files and layout are restored from the snapshots.

Not reverted by `-Undo`:

- Creating the System Restore point (the point itself stays).
- Windows updates that were installed, and any restart.
- The default browser: it is set by hand in Settings, so it is reverted by hand too.
- Keep removed apps from coming back (`bloat.persistence`): Removing provisioned packages cannot be undone (reinstall the app from the Store if needed).

## Safety

- `get.ps1` downloads the release's `install.ps1` and checks it against the published `install.ps1.sha256`; if they do not match, it does not run.
- The file in `%TEMP%` is never run directly: the elevated process (after UAC) copies it into a fresh folder under `%ProgramData%`
  that only SYSTEM and Administrators can write to, verifies the digest again there, and runs only that copy.
- **SHA-256 only catches corruption (a partial or altered download); it does not prove the source:** the digest is downloaded
  from the same place. Signing / attestation is left to later releases. `FAI_WINOP_BASEURL` (testing only) accepts only
  `https://` or `http://localhost` / `http://127.0.0.1`.
- **Elevating with another account:** if another administrator's credentials are entered at UAC, the tool runs as that account;
  HKCU settings, the desktop and taskbar / Start pins go to that account's profile, not the session owner's. In that case every
  job that needs administrator rights (the `-DryRun` preview included) stops and says who elevated and who owns the session
  (exit code 3). `-AllowOtherUser` continues on purpose. If the session owner cannot be found, it warns and continues.
  `-List`, `-ExportProfile` and `-ExportLayout` are not checked. When the tool restarts itself (UAC, `-Version`, resume after a
  restart), relative paths such as `-Profile .\x.json` are made absolute.

## Other parameters and the menu

Without a profile, the interactive menu opens. Keys: `P` preview, `A` apply, `B` back; in multi-select lists `a` all, `n` none,
`d` done. Risk tweaks ask you to type `YES`; other confirmations are `Y` / `N`.

Other parameters: `-Unattended`, `-Undo [-Session <id>] [-SkipFailed]` (skips entries that cannot be reverted and closes the session),
`-Only` / `-Skip`, `-UpdatesOn` / `-UpdatesOff`, `-ExportProfile <name>`, `-ExportLayout`, `-Version vX.Y.Z`, `-List`,
`-AllowOtherUser` (`Get-Help .\install.ps1 -Detailed`). Tweak, catalog and profile data are embedded in `install.ps1`.

## Principles

- **Settings are data, the engine is a class:** each tweak is a `.psd1` file (title, description, risk level, conditions, actions).
- **Risk levels:** `Safe` applies directly, `Caution` asks for confirmation, `Risk` makes you type `YES`; in unattended mode `Risk` is never applied.
- **Conditions:** laptop, GPU vendor, version, build number… A tweak that does not fit the hardware is skipped.
- **Reversible:** a snapshot before applying; `-DryRun` writes nothing; `-Undo -DryRun` shows from the snapshot what the state will be after the undo.
- **Profiles are open:** write your own (`profiles/`), load it from a local path or a URL. Profiles contain no personal data (passwords,
  license keys, tokens, e-mail addresses).
- **Targets Windows PowerShell 5.1** (the one that ships with Windows 11); nothing extra to install.

## Development

Development runs in WSL Ubuntu (pwsh 7 + Pester 5 + PSScriptAnalyzer); the target is Windows PowerShell 5.1.

```bash
pwsh -NoProfile -File build/Lint.ps1          # PSScriptAnalyzer + 5.1 compatibility + UTF-8 BOM
pwsh -NoProfile -c 'Invoke-Pester tests/Unit'  # unit tests
pwsh -NoProfile -File build/Bundle.ps1        # dist/install.ps1
pwsh -NoProfile -File build/TweaksDoc.ps1     # regenerate docs/TWEAKS.md
pwsh -NoProfile -File build/ProfileDoc.ps1    # regenerate the profile section of this README
tools/Sync-ToWindows.sh                       # Windows test copy + Windows Sandbox configuration
```

Rules: `.ps1 / .psd1 / .psm1` files are UTF-8 with BOM; syntax missing from 5.1 (`??`, `?.`, ternary, `&&`) is not used.
